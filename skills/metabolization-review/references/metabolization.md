# Metabolization

## Purpose

This reference explains when repeated activity has become substrate instead of remaining effortful technique. It exists to prevent premature promotion of fresh wins into enterprise operating assumptions.

## Decision Rules

- Metabolization requires settlement, repetition, time, context diversity, stability, and reduced attention burden.
- A capability used only once or in one narrow context is not metabolized.
- Repetition without stable settlement does not count.
- High maintenance or high attention burden is a warning that the capability is still brittle.

## Enterprise Notes

- Mark `substrate_candidate` before `metabolized` when evidence is promising but still thin.
- Preserve missing evidence explicitly so teams know what further settlement is required.
- Enterprise rollout should depend on metabolized capability, not on one operator's familiarity.

## Failure Modes

- Promoting a new workflow to standard body after one success.
- Ignoring context diversity and only counting repetitions.
- Confusing documentation or training with actual metabolization.
- Overlooking hidden maintenance burden that keeps attention pinned to the workflow.

Use this reference when deciding whether a capability is body or still effortful technique.
