# Framework Reconstruction

## Overview

Use this skill when the framework itself becomes the object under review. Doctrine, policies, and skills are not exempt from settlement. When they fail, reconstruct them instead of defending them as identity.

Treat the framework itself as subject to settlement, disintegration, and replacement. Preserve useful invariants, discard failed structure, and write the revised doctrine as a new candidate for future settlement.

## When To Use

Use this skill when the real issue is:

- The doctrine no longer explains reality.
- A policy creates repeated harmful or circular outcomes.
- A skill teaches behavior that fails settlement.
- The language itself is causing confusion or drift.

Do not use this skill for ordinary bugfixes or local implementation details that do not challenge the framework contract.

## Inputs

- The failing doctrine, rule, policy, or instruction surface.
- Settlement evidence showing the failure.
- Invariants worth preserving.
- Candidate replacement structures.
- Known risks if the current doctrine remains in place.

## Workflow

1. Name the failing surface precisely.
2. Describe the settlement evidence that falsifies or weakens it.
3. Separate core invariants from contingent implementation choices.
4. Identify which parts should dissolve completely and which parts should be preserved.
5. Draft a revised rule set that explains the evidence better.
6. State how the reconstructed framework should be tested in future settlement.
7. Record open questions instead of pretending the reconstruction is final truth.

## Output

Return all of the following:

- The surface that failed.
- Evidence of failure.
- Invariants preserved.
- Structure dissolved.
- Revised doctrine, policy, or instruction candidate.
- A future falsification surface.

## Common Failure Modes

- Defending doctrine because it is familiar.
- Rewriting the framework without evidence of failure.
- Throwing away useful invariants with the failed surface.
- Treating the reconstruction as final rather than provisional.
- Failing to define how the new doctrine will be tested.

Use `references/framework-invariants.md` to preserve the essential distinctions, and `scripts/reconstruct.py` when a structured reconstruction scaffold is needed.
