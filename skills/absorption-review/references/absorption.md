# Absorption

## Purpose

This reference keeps external capability review grounded. Absorption is only real when the receiving system has a pathway, acceptable payment, and a settlement plan for bringing the new material into its own body.

## Decision Rules

- External capabilities remain `potential` until a pathway into the receiving system exists.
- License compatibility, payment estimate, and settlement plan are mandatory before recommending absorption.
- If payment or policy remains unresolved, classify the candidate as `possibility`, not `absorbable`.
- Prefer the smallest absorbable fragment over importing broad external structure.

## Enterprise Notes

- Record integration burden and maintenance burden separately.
- Preserve the proposed worktree or experiment plan so absorption can be tested without hidden side effects.
- Enterprise absorption decisions should always document review gates and rollback expectations.

## Failure Modes

- Treating external capability as instantly available because it looks mature elsewhere.
- Ignoring license or compliance blockers.
- Underestimating long-tail maintenance cost.
- Absorbing entire systems when only one settled capability is needed.

Use this reference when external capability review must stay small-scope and enterprise-safe.
