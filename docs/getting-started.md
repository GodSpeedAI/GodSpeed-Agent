# Getting Started with GodSpeed-Agent

This guide gets you from zero to a running GodSpeed-Agent installation and walks you through executing your first runtime commands.

---

## 1. Prerequisites

Before installing GodSpeed-Agent, verify your local environment:
- **Operating System**: Linux, macOS, or Windows (WSL / native Python 3.11+)
- **Python**: `>=3.11`
- **Package Manager**: [`uv`](https://github.com/astral-sh/uv) (recommended)
- **Node.js**: `>=18` (optional, required only for the local RuVector semantic search sidecar)
- **Docker**: (optional, for containerized execution)

Verify Python and `uv`:
```bash
python --version   # should be Python 3.11 or newer
uv --version
```

---

## 2. Installation Options

### Option A: Development Install from Source (Recommended for Contributors)

Clone the repository and synchronize the development virtual environment:
```bash
git clone https://github.com/GodspeedAI/godspeed-agent.git
cd godspeed-agent

# Install dependencies including dev tools (pytest)
uv sync --extra dev
```

If you plan to use RuVector for local vector search:
```bash
cd tools/ruvector && npm install && cd ../..
```

Run the validation suite to confirm integrity:
```bash
uv run pytest -q
```

---

### Option B: Isolated CLI Tool via `uv tool`

To run `godspeed-nav` globally without activating virtual environments:
```bash
# From a local build:
uv build
uv tool install dist/godspeed_agent_harness-0.1.0-py3-none-any.whl

# Test installation:
godspeed-nav --help
```

---

### Option C: Containerized Execution (Docker)

If you prefer not to install Python locally:
```bash
# Build the container image
docker build -t godspeed-agent .

# Run a runtime snapshot mounted against your current workspace
docker run --rm -v "$PWD:/work" -w /work godspeed-agent \
  runtime-snapshot --workspace-root /work --storage-root .godspeed-harness
```

To include the RuVector sidecar in the container:
```bash
docker build --build-arg INSTALL_RUVECTOR=1 -t godspeed-agent .
```

## 3. Quick Smoke Test

Run a deterministic error computation directly from your shell:

```bash
uv run godspeed-nav compute-error \
  --desired '{"tests_passing": 10, "coverage": 90}' \
  --observed '{"tests_passing": 6, "coverage": 85}'
```

**Expected Output**:
```json
{
  "dominant_error": "tests_passing",
  "error_magnitude": 6.4031242374328485,
  "error_vector": {
    "coverage": 5.0,
    "tests_passing": 4.0
  }
}
```

Now evaluate the economic payment burden of a proposed candidate action:

```bash
uv run godspeed-nav estimate-payment \
  --costs '{"time_hours": 2, "compute_units": 10}' \
  --capacities '{"time_hours": 8, "compute_units": 50}'
```

**Expected Output**:
```json
{
  "capacity_norm": 50.63595560468826,
  "dominant_cost": "compute_units",
  "payment_burden": 10.198039027185569,
  "spendability": "affordable"
}
```

## 4. Understanding How the Runtime Integrates with Projects

GodSpeed-Agent is designed to observe and guide client projects without polluting their source trees.

```
/workspace/
  ├── my-project/            # Your target application project
  │   ├── src/
  │   ├── tests/
  │   ├── HARNESS.md         # (Optional) Policy configuration for this project
  │   └── .godspeed-harness/ # Local ledgers and developmental memory generated by GSA
  └── godspeed_agent/        # The GodSpeed-Agent harness installation
```

When executing commands against `my-project`, point `--workspace-root` at that project:

```bash
uv run godspeed-nav start-direction \
  --workspace-root /path/to/my-project \
  --storage-root .godspeed-harness \
  --label "Initial Feature Slice" \
  --statement "Implement user authentication with local JWT"
```

The runtime will create `.godspeed-harness/ledgers/desired_directions.jsonl` inside `my-project`.
